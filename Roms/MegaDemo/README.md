# メガデモ（音楽付き）

入力で変化する3つの演出と、同じ入力で変わる短い曲・効果音を持つ、自作の32 KiB DMG ROM Onlyです。[MITライセンス](LICENSE)で利用できます。WPFでは、デモの一覧で「Mega demo」を選んで「Run demo」を押すか、「Open ROM」で`megademo.gb`を選んでください。

| ファイル | 内容 |
| --- | --- |
| `megademo.gb` | ROM本体。SHA-256 `d1c2a4987088f97c051ecd8fe7bb008ebf9bb2c180556ee7e267a2809beea41f`、タイトル`MEGADEMO`、ヘッダー/全体チェックサムのみ設定 |
| `megademo.sym` | ラベルのアドレス（rgblink形式）。SHA-256 `6831ec01447c64cafa43dde973f2c64911a8d8551167648433f3dedb07d6d425` |
| `src/*.asm`, `src/hardware.inc` | SM83アセンブリ。フォント・星・図柄はドット絵、正弦表・マップ・模様・パレットは整数式からアセンブル時に生成。曲・音程・音色の表とシーケンサーは`src/music.asm` |
| `Build.ps1`, `Reference.ps1` | ROMの再生成/照合、別エミュレーターでの参照画像の生成/照合 |
| `reference.json`, `reference/*.png` | binjgbで描いた参照19枚と入力列・選択規則・道具の版/ハッシュ |

任天堂ロゴは含みません。ローダーのロゴ警告は意図したもので、実機のBoot ROMによる起動は検証していません。

## 操作と画面

| ボタン（WPFのキー） | 映像 | 音 |
| --- | --- | --- |
| Select（Back/Shift） | 次の演出へ（押下エッジ）。次のVBlankでLCDを止めて画面を読み込み（約0.9フレーム）、入れ直した最初のフレームは表示されない（DMGの実機と同じ）ため、約3フレーム白くなる | 音色の組（ベースの波形と音量、和音の音色、メロディーの減衰、ドラム）が演出に合わせて変わる |
| 左 / 右（方向キー） | 速度を−1 / +1（0〜7） | テンポ。毎秒5.6〜15.4ステップ（4分音符84〜231 BPM） |
| 下 / 上（方向キー） | 量を−1 / +1（0〜7）。波の振幅、プラズマの強さ、軌道の広がり | 1段ごとにCH2で短い効果音。音程は段の後の量（C5〜E6の五音音階） |
| A（Z/J） | 模様を+1（0〜3で循環）。波の配色、プラズマのタイル模様、軌道の図柄と反転 | メロディーのデューティ比（12.5 / 25 / 50 / 75%） |
| B（X/K） | 進行方向を反転（押下エッジ） | 変わらない |
| Start（Enter） | 自動進行の停止/再開（押下エッジ）。停止中も入力を受け付け、値の変更は画面へ反映する | 曲の停止（消音）/再開。再開は保存したステップから |

入力はVBlankごとに1回読みます。方向は押した読み取りで1段変わり、押し続けると20回後に次の段、以後6回ごとに繰り返します。反対方向の同時押しは打ち消し合い、上下と左右は独立です。Selectと同じ読み取りの他の入力は新しい演出へ適用します。速度・量・模様・方向は演出ごとに保持し、Startの状態は共通です。演出に入るたびに位相は0から始まります。

下端16ラインはWindowの状態表示です。1行目は演出番号と名前、RUN/STOP、2行目は`SPD`速度、量（`AMP`/`STR`/`SPR`）、模様（`PAL`/`PAT`）、`DIR+`/`DIR-`です。

StartによるROM自身の消音と、WPFのミュート・音量は別のものです。Startで止めてもアプリの音声出力は動いたまま（ROMが無音のPCMを作る）で、ミュートや音量はROMの状態を変えません。

## 演出の定義

s(a, A)は1周256単位の正弦をBhaskara Iの有理式で近似し、振幅Aを掛けて四捨五入した整数です（後半は負）。h = a mod 128として s = 16h(128−h) / (5·128² − 4h(128−h))。浮動小数点を使わないため、テストで全値を再計算できます。16 bitの位相は実行中に毎フレーム(速度+1)×128ずつ進み（反転時は戻り）、上位バイトを角度θとします。

| 演出 | 構成 | 入力の効果 |
| --- | --- | --- |
| 1 WAVE | 斜めの濃淡・菱形のタイルと文字行。ラインyのSCX = s(2y + θ, 8×量) を算術右シフト1。BGPは基本色に、中心64 + s(2θ, 48)の暗い帯と64 + s(2θ+128, 48)の明るい帯（各15ライン、中心からd離れた行は各濃淡を(7−d)/2段移動）を重ねる | 速度、振幅、配色（標準/反転/淡色/影絵）、波の向き |
| 2 PLASMA | 32×32タイルの段階 ((s(16x)+s(24y)+s(8(3x+2y))+s(16(x−y))+256) >> 5) mod 16（振幅64）。段階Lは色L/4と次の色を(L mod 4)/4の割合で混ぜる16タイル。SCX = θ + s(4y + 2θ, 16)/4、SCY = s(θ, 24)、色cの濃淡は floor((21 + (2v−3)×強さ + 7)/14)、v = (c + θ/32) mod 4 | 速度、強さ（0で一様な灰色）、模様（2×2組織的ディザ/横線/縦線/斜線）、方向 |
| 3 ORBIT | 星のBGを8ライン帯ごとに1/2/3倍速でSCXスクロール。5周×8個＝OAM 40個。周rのk番目は角度(r+1)θ + 32k、半径段 min(7, (広がり×(r+2)+3)/6)、X = 84 + s(a+64, 8×段)、Y = 76 + s(a, 8×段)。図柄は(r+模様) mod 4、奇数周はOBP1、周2はBGの後ろ、奇数番は模様のbit0/1でX/Y反転 | 速度、広がり（0で40個が同じラインに重なり、ラインあたり10個だけ表示）、図柄/反転、回転方向 |

プラズマの模様変更は16タイル256 bytesを64 bytesずつ4回のVBlankで転送し、途中の画面は新旧の模様が混ざります。

## 音楽

16分音符64ステップ（4小節、Am | F | C | G）の繰り返しです。CH1がメロディー、CH2が和音の分散、CH3（Wave）がベース、CH4（Noise）がキック・スネア・ハイハットを鳴らします。ROMがAPUのレジスタを直接書いて演奏し、エミュレーター側に曲の知識はありません。

**曲の表:** `Song`の1行が1ステップで、メロディー・和音・ベース・ドラムの4 bytesです。256 bytesの1ページに置き、ステップ番号×4で直接引きます。音符のバイトは0が前の音を保持、1が消音、2以上はMIDIノート番号−34（C2 = 36が2）。Waveは同じ周期のPulseより1オクターブ低く鳴るため、ベースは1オクターブ上を格納します（ソースの`step`マクロは実際に鳴る音名で書き、変換はマクロが行う）。ドラムは0なし、1キック、2スネア、3ハイハット。音程表`NoteTable`はMIDI 36〜96のPulse周期 round(2048 − 131072 / f)、f = 440 × 2^((n − 69) / 12) です。

**テンポ:** 表示したフレームごとに1回、8 bitの端数へ 24 + 6 × 速度 を足し、桁上がりで次のステップを鳴らします。毎秒 59.73 × (24 + 6 × 速度) / 256 ステップで、速度0が5.6（84 BPM）、既定の3が9.8（147 BPM）、7が15.4（231 BPM）。1周は既定で約6.5秒です。

**効果音:** 上下の段ごと（押下とリピート。量が0や7で変わらない段も含む）に、CH2を8フレームの間効果音に使います（デューティ50%、音量15から減衰、NR22 = $F1）。音程は量0〜7の順にC5・D5・E5・G5・A5・C6・D6・E6。その間に来た和音の音符は鳴らさず、8フレーム後の次の音符から和音に戻ります。

**音色の組:** 演出ごとに次の値を使います。演出を切り替えたフレームで読み込み、波形RAMはCH3のDACを止めて書き換え、鳴っていたベースは新しい波形で鳴らし直します。

| 演出 | メロディーの減衰（NR12） | 和音（NR21のデューティ、NR22） | ベース（波形、NR32の音量） | ドラム（キック・スネア・ハイハットのNR42/NR43） |
| --- | --- | --- | --- | --- |
| 1 WAVE | $A3（音量10、3段ごと） | 25%、$62 | 三角波、100% | $F1/$54、$C2/$33、$81/$01 |
| 2 PLASMA | $87（音量8、長い減衰） | 50%、$53 | のこぎり波、50% | $F1/$55、$B2/$34、$51/$01（ハイハットを弱く） |
| 3 ORBIT | $C2（音量12、短い減衰） | 12.5%、$71 | 矩形波、50% | $F2/$64、$C2/$33、$71/$09（長いキック、7 bitの金属的なハイハット） |

**ベースの鳴らし直し:** ベースの音符ごとに、NR30へ0を書いてCH3を止めてから$80を書き、NR34で鳴らします。DMGでは、鳴っているCH3を鳴らし直すとき、その瞬間がWave RAMの読み出しと重なるとWave RAMの先頭が書き換わり（Pan Docs NR34の注意）、重なるかはメインループがここに来るT-cycleで決まります。止めずに鳴らし直すと、HBlankのSTAT割り込み処理の開始が数T動いただけで3.76秒のベースの音でWave RAMが壊れ、以後のベースの音色が変わります。

**定位:** NR51 = $7D（左: CH1・CH2・CH3、右: CH1・CH3・CH4）、NR50 = $77。和音は左だけ、ドラムは右だけで、メロディーとベースは中央です。

**Start:** 停止するとNR51を0にして何も出力しません。チャネルは動いたままで、ステップ・テンポの端数・各チャネルの最後の音符を保持し、停止したフレームでも曲は進みません。停止中はテンポ・効果音・音色の読み込みを処理しません（演出や量の変更は映像に反映され、音色は再開したフレームで読み込む）。再開するとNR51を戻し、保存したステップで最後に鳴らした音符（メロディー・和音・ベース。消音中のものを除く）をエンベロープの初期値から鳴らし直し、同じステップの続きから進めます。ドラムは鳴らし直しません。

**処理の位置:** 起動時は最初のフレームの前にAPUを一度OFFにしてから（全レジスタを消去）ONにし、ステップ0を鳴らします。以後はメインループが入力処理の直後に1フレーム1回だけ呼び、割り込みでは動かしません。DI/HALTも使いません。

## 処理の流れと時間

- **VBlank割り込み**: Joypadを読み、メインループが作り終えたフレームを表示へ反映する（HRAMからのOAM DMA、ラスター表の表/裏の交換、SCY、状態表示2行40 bytes、未転送のタイル64 bytesまで）。作り終えていなければ前の画面を保ち、`wLagFrames`を加算する。演出の切り替え時はここでLCDを止め、マップを読み込み、最初のフレームを表示してLCDを再開する。
- **STAT（HBlank）割り込み**: ラインLのHBlankで、ラインL+1用に用意したSCX/BGPを書く。分岐のない38 M-cycle（受理5を含め43）で、SCXは受理から27、BGPは33 M-cycle目。Mode 3中にレジスタやVRAMを書き換えない。
- **メインループ**: 入力を処理し、曲を1フレーム分進め、次のフレームの全ライン表・影OAM・状態文字列を裏側へ作る。映像のハードウェアへ直接書かないため、フレーム内のどこで動いても画面は同じになる（HALT実行中に割り込みが来るとHALTへ戻るため、次の割り込みまで再開が遅れることがある）。APUへの書き込みは起動時の初期化とこのループからだけ行う。

BGPはHBlank開始から150 dots以内に書きます。Mode 3が最短（SCX mod 8が0でSpriteなし）のラインでは、HBlank割り込みがDot 254に起き、CPUはDot 256から見て、実行中の命令（メインループで最長のCALL、6 M-cycle）は遅くともDot 276に終わり、受理から32 M-cycle後のDot 404にBGPを書きます。Mode 3はSCX mod 8とそのラインのSpriteで伸び、Pan Docsの最長289 dotsでもHBlankはDot 373までに始まるため、書き込みは遅くともDot 523（次ラインのDot 67）で、次ラインの描画開始（Dot 84）より先に終わります。Core.Testsの実測（各演出の最大量、タイル転送を含む60フレーム）では、全144ラインの書き込みがHBlankのラインのDot 360〜456（456は次ラインのDot 0）でした。曲の処理はCALLが多いため、受理がCALLの直後になる最悪の場合が上限どおりに現れます。VBlank処理は最長でライン144開始から3,816 dots（ライン152のDot 168）で終わり、ライン0のHBlank割り込みを遅らせません。`wLagFrames`は0のままです。

## ビルドと照合

通常のアプリのビルド・テストにアセンブラーは不要で、コミット済みの`megademo.gb`/`megademo.sym`を使います。再生成はWindowsのPowerShell 7で次を実行します。

```powershell
./Roms/MegaDemo/Build.ps1            # 再アセンブルして2ファイルを置き換え、SHA-256を表示
./Roms/MegaDemo/Build.ps1 -Verify    # .cache内で再アセンブルし、コミット済みとバイト単位で比較
```

アセンブラーは[RGBDS v1.0.4](https://github.com/gbdev/rgbds/releases/tag/v1.0.4)（MIT、[LICENSE](https://github.com/gbdev/rgbds/blob/v1.0.4/LICENSE)のSHA-256 `776850497a707cc8183b19b774cf73dd0d79428cb1c51e452a940875be1e292c`）に固定します。初回だけ`rgbds-win64.zip`（SHA-256 `bd1d7e386f290afd57f4ea9a7353bfcd4ae10884a94c5c1f2fc42a75db7f97e6`）を`.cache/rgbds`へ取得し、`rgbasm`/`rgblink`/`rgbfix`の各SHA-256も照合します。以後は`-Offline`でネットワークなしに再生成・照合できます。コマンドは`rgbasm -Wall -Wextra`、`rgblink -d -t -p 0xFF`、`rgbfix -f hg -p 0xFF -t MEGADEMO`です。

## 別エミュレーターとの照合

```powershell
./Roms/MegaDemo/Reference.ps1 -Offline -Verify   # 参照19枚を描き直し、画素をコミット済みと比較
```

参照画像は[binjgb v0.1.11](https://github.com/binji/binjgb/releases/tag/v0.1.11)（MIT、LICENSEのSHA-256 `89807acf2309bd285f033404ee78581602f3cd9b819a16ac2f0e5f60ff4a473e`）の`binjgb-tester`で作ります。`binjgb-windows.tar.gz`のSHA-256は`86ebb0f68d760b30c8162f788bda472ba856b9ac7dd7ee89c69ad751456f3e66`、`binjgb-tester.exe`は`e43c0eeec94738f051cf705ef017fe5d2689b8dde8938d560a4819cbda5e32e6`です。binjgbはヘッダーのロゴを検査するため、`.cache/megademo-reference`の一時コピーにだけ`rgbfix -f lhg`でロゴとチェックサムを書きます（0104〜0133と014D〜014F以外が同じことをスクリプトが確認）。

起動方法は`binjgb-tester -j input.joyp -f N -o frame.ppm megademo-logo.gb`で、電源投入からN×70,224 T以後に最初に完成したフレームを出力します。入力はフレームの中ほど（(N+0.5)×70,224 T）で変え、VBlankの読み取りから離します。binjgbは既定で反対方向の同時押しの片方を落とす（ホスト側の方針で、DMGの配線ではない）ため、参照用の入力列は反対方向を同時に押しません。打ち消し規則はCore.Testsで確認します。LCDを有効にした直後の4フレームをbinjgbは出力しないため、選ぶフレームは演出の切り替えから8フレーム以上離しています。

Core.Testsの`MegaDemoTests`は同じ入力をT-cycle単位で与え、19枚すべてを全画素で比較します。テスト中にbinjgb・RGBDSを起動したりダウンロードしたりしません。曲の追加後もROMの映像は変わらず、19枚は描き直しても同じ画素で、`reference.json`はROMのハッシュだけが変わりました。

**音:**

```powershell
./Roms/MegaDemo/Compare-Audio.ps1 -Offline   # binjgbの音とスペクトルで比べ、聴き比べ用のWAVも書く
```

同じbinjgbの`binjgb.exe`（SHA-256 `33955789bc71a4bc16543dd7bc2597804e347376f900bf905fbc24e835b6282c`、`SDL2.dll`は`f65b50d693484d5d5a2bb8df1cf520628dd744e99e9a937bb936839b990943a0`）をSDLのディスク出力（環境変数`SDL_AUDIODRIVER=disk`、`SDL_DISKAUDIOFILE=<出力>`）で起動し、ロゴを書いた一時コピーを無入力で約16秒鳴らします。binjgbのウィンドウが開きますが、音は再生しません。出力は44.1 kHz・ステレオ・32 bit浮動小数点の生PCMで、ウィンドウを閉じて正常終了させると最後まで書かれます。[CompareAudio.cs](CompareAudio.cs)がCoreの`Audio.ReadFrames`で電源投入から14秒のPCMを作って比べ、`.cache/megademo-audio`へ`metrics.json`と`ours.wav`（48 kHz）・`binjgb.wav`（44.1 kHz、左右を戻して直流を除いたもの）を書きます。binjgbの開始は280〜370 ms遅いため、包絡で位置を合わせます。記録した結果は次のとおりです。

| 項目 | 結果 |
| --- | --- |
| 音量の包絡（10 msごとのRMS、13秒）の相関 | 0.965 |
| 93 msごとのスペクトル（60 Hz〜5 kHz）のコサイン類似度、139窓 | 左 平均0.991・中央値0.999・下位10% 0.988、右 平均0.993・中央値0.997・下位10% 0.985 |
| 各窓で最も強い周波数の一致（2%または12 Hz以内） | 278窓中270 |
| 左右のRMS比（左/右の中央値） | このエミュレーター0.933、binjgb 0.934 |

スクリプトは、類似度の平均0.98・下位10% 0.95・最も強い周波数の一致95%・包絡の相関0.9をすべて満たすと成功とし、下回ると失敗で終わります。binjgbはSO1（右の端子）を先に書くため左右が逆に並び、出力の高域通過フィルター（直流の除去）がなく0〜1の単極の値です。比較では左右を入れ替え、両方に同じ10 msの移動平均を引く処理をかけます。アナログ部の特性・機種差・リサンプリングは合わせていないため、波形のbit一致は求めません。聴感は人が2つのWAVを聴き比べて評価します。
