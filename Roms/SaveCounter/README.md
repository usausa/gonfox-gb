# セーブRAMのカウンターデモ

本リポジトリで作成したMITライセンスの最小ROM。標準MBC1、ROM 64 KiB、電池RAM 32 KiB。生成は`./Roms/SaveCounter/Build.ps1`。外部アセンブラーや任天堂のコード・画像は不要。

ROM全体のSHA-256は`8a10e1cfe0670319a2f3725c155aca31370135e1b06bb3c880af62f2b1438673`。

WPFの「Open ROM」で`save-counter.gb`を選ぶ。起動するとA000の値が1増え、「Debug」の行のSCXに表示される。画面は値の下位2bitに応じて白・薄灰・濃灰・黒を循環する。保存ファイルがない初回の値は1。

「Save RAM」、別ROMへの切り替え、通常終了で保存するほか、実行中も値が変わってから5秒たつと実行を止めずに保存する（定期保存）。アプリを起動し直して同じROMを開くと値が続きから増える。同じROMを再読み込みした場合と「Reset」でも、RAMを保持したまま起動処理が再実行される。256回で0へ折り返す。入力ボタンはこのROMでは使用しない。

保存先は`%LOCALAPPDATA%/GonFox.GameBoy/Saves/<ROM全体のSHA-256>.sav`で、WPFにも表示される。これはカートリッジのRAM保存であり、CPUやPPUを保存地点から再開する機能ではない。

Nintendoロゴ領域はゼロにしてあるため、ローダーのロゴ警告は意図したもの。Boot ROM省略プロファイル用で、実機Boot ROMでの起動は対象外。

WPFのサンプルで、通常終了→再起動の1→2、Resetの2→3、保存先がロックされているときのRAMの保持と解除後の再保存、定期保存（実行中のまま約8秒で保存し、前の世代は`.sav.bak`へ）、同じROMを2つ目のアプリで開くと読み込みを断ることを確かめられます。保存の契約は[現行仕様](../../docs/Specification.md)、検証は[互換性と検証](../../docs/Compatibility.md)を参照。
