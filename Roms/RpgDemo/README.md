# RPGデモ（USAGI QUEST）

起動ロゴ・勇者と難易度の選択・コマンド式の戦闘・全ボタンの確認画面を持ち、各画面でBGMが流れる、自作の32 KiB DMG ROM Onlyのゲームもどきです。[MITライセンス](LICENSE)で利用できます。WPFではデモの一覧で「RPG demo」を選んで「Run demo」を、MAUI（Android）では「Demo」から「RPG demo」を選ぶか、「Open ROM」で`rpgdemo.gb`を選んでください。

| ファイル | 内容 |
| --- | --- |
| `rpgdemo.gb` | ROM本体。SHA-256 `f4273fef8d77505bf0d6ad81ad3dac0083e94a7e034331452c9274c6eea74644`、タイトル`USAGI QUEST`、ヘッダー/全体チェックサムのみ設定 |
| `rpgdemo.sym` | ラベルのアドレス（rgblink形式）。SHA-256 `89f76c9c74b0ba598f6ae8e44b43f885134693841266641ebe0226f81e024427` |
| `src/*.asm`, `src/*.inc` | SM83アセンブリ。`rpgdemo.asm`が土台（フレーム処理・影マップ・タイル転送・入力・乱数）、場面ごとに`title`・`select`・`battle`・`keytest`、文章は`text`、曲・効果音は`music`、絵と名前の表は`data` |
| `art/*.png` | ドット絵（フォント、枠とHPバー、タイトルの風景とロゴ、勇者8人の歩き・顔・後ろ姿、敵3体、足場、効果、パッド）。`Build.ps1`がrgbgfxでタイルへ変換する |
| `Build.ps1`, `Reference.ps1` | ROMの再生成/照合、別エミュレーターでの参照画像の生成/照合 |
| `reference.json`, `reference/*.png` | binjgbで描いた参照22枚と入力列・選択規則・道具の版/ハッシュ |

勇者8人と敵3体は、依頼時に示されたテンプレートアプリのキャラクター・モンスター画像を参考に、マイクラ風の四角いドット絵として描き起こしたものです（元の画像は含みません）。任天堂ロゴは含みません。ローダーのロゴ警告は意図したもので、実機のBoot ROMによる起動は検証していません。

## 画面と操作

| 画面 | 内容 | 操作 |
| --- | --- | --- |
| タイトル | 夜空から地上へ背景が160フレームかけて下りる（SCY 0→112、終わりほど遅く）。`USAGI QUEST`の10文字が7フレームおきに上から落ちて止まり、画面が光る。2段の道を勇者8人が歩き、`PUSH START`が点滅する（48フレーム表示、16フレーム消灯） | StartかAで、背景と文字の途中なら完成したロゴへ飛ばし、`PUSH START`ならメニュー（GAME START / KEY TEST）を開く。メニューは上下・Selectで選び、AかStartで決定、Bで閉じる |
| 勇者と難易度の選択 | 上に勇者の顔・名前・魔法・番号、下に難易度（EASY / NORMAL / NIGHTMARE）とその敵 | 左右・Selectで勇者（8人で一周）、上下で難易度（両端で止まる）、AかStartで戦闘、Bでタイトルへ |
| 戦闘 | 右上に敵とその足場、左上に敵の名前・Lv・HPバー、左下に勇者の後ろ姿、その右に勇者の名前・Lv10・HPバーと数値・MP、下に文章の枠 | 十字キーでコマンド（上下で行、左右で列）、Aで決定。Selectで次の立っている勇者と交代、Startで一時停止（曲も止まる。もう一度Startで再開）。文章は1フレーム1文字で出て（AかBを押している間は一度に）、▼が出たらAかBで次へ |
| KEY TEST | パッドの絵（押している部品が凹む）、押しているボタンの名前（`U D L R A B SE ST`、押していないものは`.`）、押した回数（5桁） | 各ボタンを新たに押すたびに1回数え、ボタンごとの音を鳴らす。StartとSelectを同時に押すとタイトルへ |

入力はVBlankごとに1回読みます。方向は押した読み取りで1回効き、押し続けると20回後に再び、以後6回ごとに繰り返します（メニュー・選択・戦闘のコマンド）。場面を移るときは白へフェードし、LCDを止めて絵を読み込み、白からフェードします。フェードが終わるまで（開始から16フレーム）入力は受け付けません。

選択画面の顔（16タイル）と敵（36タイル）は、選んだ後のVBlankで少しずつ転送します。転送中も次の入力を受け付け、転送が空いたときに、その時点の選択と違う絵（顔を先に）を転送し直します。前の転送の終わりを待ってから送る方式では、その間（敵は18フレーム）の入力を落とすためです。

## 戦闘のルール

戦闘は勇者の行動、敵が残っていれば敵の攻撃、の順に進みます。勇者は全員Lv10・HP 50で、MPは3を全員で使います（戦闘ごとに全回復）。

| コマンド | 効果 |
| --- | --- |
| FIGHT | 8 + R(5) のダメージ。R(8) = 0 なら急所で2倍（16〜24） |
| MAGIC | MPを1使い、14 + R(7) のダメージ。MPが0なら「Not enough MP!」でコマンドへ戻る（ターンを使わない） |
| GUARD | 次の敵の攻撃を半分（切り捨て、最低1）にし、HPを4回復（50まで） |
| RUN | EASYは必ず、NORMALはR(2) = 0なら、NIGHTMAREは逃げられない。逃げられなければ敵の攻撃 |
| Select（交代） | 次の番号から数えて最初のHPが残っている勇者を出す。ターンを使う |

| 難易度 | 敵 | Lv | HP | 攻撃 | 必殺技（2倍） | EXP |
| --- | --- | --- | --- | --- | --- | --- |
| EASY | SLIME CAT | 5 | 30 | BOUNCE 3 + R(4) | なし | 40 |
| NORMAL | KING CAT | 25 | 60 | ROYAL PAW 5 + R(5) | 4ターンごとに CROWN DROP | 120 |
| NIGHTMARE | SHADOWCAT | 99 | 99 | SHADOW BITE 7 + R(6) | 3ターンごとに DARK DREAM | 250 |

勇者は SERA（HOLY LIGHT）、PINA（HEART BEAM）、SHIRO（MOON BLADE）、KURO（DARK WING）、YUKI（ICE STORM）、AKANE（FOX FIRE）、YORU（NIGHT RAIN）、HANA（PETAL DANCE）の8人で、かっこ内は魔法の名前です。HPが0になった勇者は倒れ、次の番号から数えて最初のHPが残っている勇者が出ます。全員が倒れるとGAME OVER、敵のHPが0になると勝ち（EXPを表示）、どちらも文章の後と逃げた後はタイトルへ戻ります。必殺技は敵のN回目、2N回目……の攻撃（Nは表の値）で、敵の攻撃を数えたものが`wTurn`です。

**乱数:** R(n)は16 bitのxorshift（x ^= x << 7、x ^= x >> 9、x ^= x << 8）を1回進め、新しい値の上位バイトをnで割った余りです。初期値は$E1ACで、毎フレーム1回（ジョイパッドを読んだ直後）と、R(n)を使うたびに1回進みます。押したフレームが同じなら結果も同じです。

KEY TESTは曲を止め（`wSongId` = 0）、ボタンの音だけを鳴らします。

**曲の表:** 曲は見出し（テンポ値、繰り返し、上の6つの音色の値、ドラムの組）と、16行のパターンの並び（0で終わり）です。1行が16分音符で、メロディー・和音・ベース・ドラムの4 bytesです。音符のバイトは0が前の音を保持、1が消音、2以上はMIDIノート番号−34（C2 = 36が2）。Waveは同じ周期のPulseより1オクターブ低く鳴るため、ベースは1オクターブ上を格納します（ソースの`step`マクロは実際に鳴る音名で書く）。ドラムは0なし、1キック、2スネア、3ハイハット。音程表`NoteTable`はMIDI 36〜96のPulse周期 round(2048 − 131072 / f)、f = 440 × 2^((n − 69) / 12) です。

**テンポ:** VBlankごとに1回、8 bitの端数へテンポ値を足し、桁上がりで次の行を鳴らします。毎秒 59.73 × テンポ値 / 256 行、4行が1拍です。16行の後は次のパターンへ進み、並びの終わりで最初へ戻るか（繰り返す曲）、止まります（勝利と全滅。最後の行の消音で3音とも止まる）。曲を始めると1行目をすぐ鳴らします。

**ドラムの組（キック・スネア・ハイハットのNR42/NR43）:** ロック $D1/$54、$B2/$33、$71/$01。マーチ $D1/$55、$A3/$23、$61/$01。ソフト $91/$55、$72/$33、$41/$01。

**ベースの鳴らし直し:** ベースの音符ごとにNR30へ0、$80を書いてCH3を止めてから鳴らします（鳴っているCH3の鳴らし直しがWave RAMの読み出しと重なるとDMGはWave RAMを壊すため。メガデモと同じ）。

**効果音:** 音の効果音はCH2を、雑音の効果音はCH4を、鳴っている間だけ借ります。その間の和音・ドラムは鳴らさず、和音は効果音の後の次の音符から戻ります。カーソル移動（E6）、決定（A5→E6）、取り消し（E5→A4）、文章送り（C6）、ロゴの文字の着地（雑音）、ロゴの光（C6 E6 G6 C7）、FIGHTの命中（雑音）、MAGIC（C5からC7への分散和音）、勇者への命中（雑音）、GUARDの回復（C5 E5 G5 C6）、倒れる（G5 E5 C5 G4 C4）、交代と逃走（C6 G5 C6）。KEY TESTのボタンの音は A C6、B A5、Select E5、Start G5、右 D6、左 B5、上 F6、下 G4 で、同時に押したときはパッドのバイト（A, B, Select, Start, 右, 左, 上, 下 の順のbit 0〜7）で下位のボタンの音です。

**一時停止:** 戦闘中のStartでNR51を0にして何も出力せず、行・端数・効果音を進めません。もう一度StartでNR51を戻し、同じ行・端数から続けます。

## 処理の流れと時間

- **メインループ**: 変えた影マップの行を確定してHALTで待ち、VBlankの後にジョイパッドを1回読み、乱数を1回進め、場面の処理を1回行う。戦闘や文章のように、場面の処理の中でフレームを待つこともある（`NextFrame`）。場面の終わりで`wNextScene`を書くと、メインループがLCDを止めて次の場面を読み込む。
- **VBlank割り込み**: HRAMからのOAM DMA、スクロールとパレットのレジスタ、確定した影マップの行を最大2行、続いてタイル転送を2タイル（マップの行を写したVBlankは1タイル）、の順でVRAMとOAMを書き、その後に曲を1フレーム分進める（APUだけを書く）。

VBlankのVRAMの書き込みは、VBlankの開始（ライン144）から最長4,172 T（ライン153のDot 68）で終わり、VBlankの4,560 Tに収まります（Core.Testsの実測。参照用の全行程1,976回と、選択画面で2フレームごとに入力を変え続けたときの両方で同じ最大値）。転送はタイル単位の展開したコピーで、マップの行を写すVBlankは1タイルだけ送ります。マップ2行の後に32 bytesを続けると、VBlankを越えた最後のバイトがライン0のMode 3に入り、選択画面の顔と敵の絵が欠けます（binjgbでも同じ欠け方になる、ROMの側の制約です）。

電源投入時は、WRAM・VRAMを消去してタイトルを読み込む間、LCDを約14フレーム（0.23秒）止めます。

## ビルドと照合

通常のアプリのビルド・テストにアセンブラーは不要で、コミット済みの`rpgdemo.gb`/`rpgdemo.sym`を使います。再生成はWindowsのPowerShell 7で次を実行します。

```powershell
./Roms/RpgDemo/Build.ps1            # 絵を変換・再アセンブルして2ファイルを置き換え、SHA-256を表示
./Roms/RpgDemo/Build.ps1 -Verify    # .cache内で再生成し、コミット済みとバイト単位で比較
```

アセンブラーはメガデモと同じ[RGBDS v1.0.4](https://github.com/gbdev/rgbds/releases/tag/v1.0.4)（MIT、`rgbds-win64.zip`のSHA-256 `bd1d7e386f290afd57f4ea9a7353bfcd4ae10884a94c5c1f2fc42a75db7f97e6`）で、`rgbasm`/`rgblink`/`rgbfix`に加えて`rgbgfx`（SHA-256 `8ad164fb42cb626188ced7fd24648bd237f307660585e90dd6402942765d15f4`）も照合します。初回だけ`.cache/rgbds`へ取得し、以後は`-Offline`でネットワークなしに再生成・照合できます。

絵は`rgbgfx`で2bppのタイルにします。背景の絵は白・明るい灰・暗い灰・黒（`#FFFFFF,#AAAAAA,#555555,#000000`）を色0〜3に、物体の絵はマゼンタを透明な色0にし、歩く勇者と効果は白・明るい灰・黒（OBP0 = $D0）、落ちる文字は白・明るい灰・暗い灰（OBP1 = $90）です。タイトルの風景とロゴは重複タイルをまとめてマップを作り（`-u -t`、ロゴは風景の後の番号から`-b`）、両方で33 + 23タイルです。8×16の物体は列ごとの順（`-Z`）にします。コマンドは`rgbasm -Wall -Wextra`、`rgblink -d -t -p 0xFF`、`rgbfix -f hg -p 0xFF -t 'USAGI QUEST'`です。

## 別エミュレーターとの照合

```powershell
./Roms/RpgDemo/Reference.ps1 -Offline -Verify   # 参照22枚を描き直し、画素をコミット済みと比較
```

参照画像はメガデモと同じ[binjgb v0.1.11](https://github.com/binji/binjgb/releases/tag/v0.1.11)の`binjgb-tester`（SHA-256 `e43c0eeec94738f051cf705ef017fe5d2689b8dde8938d560a4819cbda5e32e6`）で作り、binjgbのロゴ検査のため`.cache/rpgdemo-reference`の一時コピーにだけ`rgbfix -f lhg`でロゴとチェックサムを書きます。電源投入からN×70,224 T以後に最初に完成したフレームを出力し、入力はフレームの中ほど（(N+0.5)×70,224 T）で変えます。乱数はフレームごとに進むため、押すフレームを固定すれば戦闘の数値も固定されます。

入力列はタイトルを飛ばしてGAME STARTへ進み、PINAとEASYを選び（途中でNORMALの敵も表示）、FIGHT・MAGIC・一時停止・SHIROとの交代・MAGICで勝ち、タイトルへ戻ってKEY TESTで全ボタンを押します。22枚は、夜空の背景、落ちる文字、`PUSH START`と歩く勇者、メニュー2枚、選択3枚、戦闘10枚（出現、コマンド、FIGHTの命中、ダメージ、敵の攻撃で揺れる画面、MAGICの星、一時停止、SHIROの登場、沈む敵、勝利）、KEY TEST 4枚です。LCDを有効にした直後の4フレームをbinjgbは出力しないため、選ぶフレームは場面の読み込みから8フレーム以上離しています。

Core.Testsの`RpgDemoTests`は同じ入力をT-cycle単位で与え、22枚すべてを全画素で比較します。テスト中にbinjgb・RGBDSを起動したりダウンロードしたりしません。

## 検証

`RpgDemoTests`（Romカテゴリ、21件）が次を確認します。

- ROMと画面（5件）: ヘッダー・ROM Only・観測ラベルのアドレス・割り込みベクター・敵の表。binjgbの参照22枚と、その全行程でVBlankのVRAMの書き込みがVBlank内で終わること。タイトルの飛ばし・メニュー（上下・Select・B・A）と選択画面（勇者の一周、難易度の両端、Bで戻る、表示の文字）。KEY TESTの押した数・押しているボタンの名前と表示・ボタンごとの音の周期（平均律から計算）・Start+Selectでの戻り。選択画面で2フレームごとに入力を変えたときのVBlankの時間と、最後の選択の顔と敵のタイルがROMのタイルと一致すること。
- 戦闘（5件）: 人と同じボタン操作（文章はA、コマンドは十字キーとA、交代はSelect）で戦い、ROMが乱数を引いた瞬間の状態から上の式で計算した数値と、毎ターンの敵と勇者全員のHP・MP・ターン数・結果・曲・EXPを比べる。EASYの勝利と必ず逃げられること、NORMALのMP切れ・GUARD・交代・R(2)での逃走、NIGHTMAREの3ターンごとの必殺技・倒れた勇者の交代・勝利、全員が倒れてGAME OVER、Startでの一時停止（NR51 = 0、曲の行と端数の保持、Aは効かない、再開）。戦闘の後の勇者と敵のタイルも確認します。
- 音楽（11件）: 音程表を平均律から再計算した値。5曲のテンポ・繰り返し・パターン数・音符が調の音階に入ること・各パターンで3音とも鳴ること。タイトル・選択・戦闘の曲を1周以上、毎フレーム、行・端数・パターン・CH1〜CH3の周期と音色・ベースの音量と波形・ドラムの音色・NR50/NR51を、上の規則で書いた曲のモデルと比べる。勝利と全滅の曲が1回で止まり、3音が消音のまま続くこと。

期待値はこのREADMEの規則・ROMの表・別エミュレーターの画面から決め、このエミュレーターの出力を後から正解として固定したものはありません。結果と比較条件は[互換性と検証](../../docs/Compatibility.md)にまとめています。
